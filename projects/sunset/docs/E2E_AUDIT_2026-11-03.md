## Hosted browser and recovered file

The fresh run visited [the published site](https://sunset-lemon.vercel.app) using isolated task profiles and verified the pinned testnet reader. Desktop **1920 × 1080** and mobile-width **390 × 844** landing navigation loaded images without horizontal overflow. The player dialog and controls also fit at 390 pixels. This is viewport QA, not a physical-device or full accessibility audit.

Original and steward-selected manifests recovered successfully and produced byte-identical **7,246-byte** standalone downloads, SHA-256 `fbe1df06b5eb4a93aae1eb12009f4d910e3ba432862918e3c254fc013ab79738`. The first mirror request timed out and the UI displayed the timeout; one bounded retry succeeded. No commitment mismatch or hosted JavaScript page error was observed. Both mirror paths use the same Vercel host, so this proves mirror selection and verified retrieval, not independent hosting resilience.

The hosted game checked both wrong-answer and correct-answer feedback, score updates and disabled alternate choices. A complete five-question hosted run was not repeated. The actual original-resource browser download was opened in a separate fresh browser profile, with **Chromium DevTools offline enabled before navigating to the file**. It completed all five questions and restarted correctly, with `navigator.onLine=false`, zero HTTP requests/resource entries and no page errors. The operating-system network adapter was not disabled.

Generated screenshots, browser profiles and raw QA logs remain local and ignored; public evidence contains their safe hashes and results. No user browser profile or wallet credentials were accessed by this browser run.
